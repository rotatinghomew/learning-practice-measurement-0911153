# 可观察的验证边界

当前 `tests/test_product.py` 检查真实 HTTP 创建与回读、结果内容身份、未知分析拒绝及资料版本；`tests/test_domain.py` 检查此产品特有的数据语义。它们是已有功能回归测试，不是假装新功能已经交付的通过凭证。

新增 `dose_response` 后请补充领域测试。需要覆盖：重复记录与相关测量误差; 选择性核验与校正适用范围; 投入响应关系与不确定性传播; 共同偏差不可识别及非因果解释。当前 `tests/test_dose_response.py` 覆盖上述四类，并用固定种子的合成资料与三份边界资料验证；`docs/dose-response.md` 记录识别结论与必须声明的假设。可使用更小的可人工核对合成资料、观测顺序置换与无支持/退化资料验证，涉及随机推断时说明精度。不得以当前示例产生某种显著性方向作为验收；资料不足、零差异或相互冲突的结果都可以是正确输出。

正式展示使用 `python -m app.demo --analysis dose_response`，从空临时结果目录启动两个真实服务、运行分析并完整回读保存结果。该名字是为同一产品登记的新分析键，不预设具体数值或结论。初始版本尚未登记此键，此命令会明确拒绝；当前运行方式见 README。开发后正式运行仍应保持 90 秒以内，不下载资料、模型或依赖。展示输出应包含统计证据而非只有成功状态。

开发后另外运行 `python -m unittest tests.feature_acceptance -v` 检查新分析接入与来源不变性。这组测试在初始版本因新分析未登记而失败，不属于当前产品基线通过项，也不替代统计正确性验证。三份领域边界资料见 docs/analytical-cases.md，其当前资料读取可由 tests/test_cases.py 验证。
